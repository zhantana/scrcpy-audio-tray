# 变更：投屏改为带菜单栏的应用窗口

## Why

现在投屏画面是 scrcpy 自己的裸窗口，只有系统标题栏（最小化 / 最大化 / 关闭），没有任何菜单。切设备、暂停媒体、置顶、改帧率都得回头右键托盘图标，操作路径和「正在看画面」这个场景是割裂的。

用户要的是常规 Windows 程序那种窗口：顶上一行里排着「设备 / 音频 / 视图 / 帮助 / 关于」菜单，功能就在画面所在的那个窗口里，不用去别处找。菜单和标题要在同一行，不能标题栏一行、菜单栏又一行。

scrcpy 本身没有菜单栏，也没有留接口让外部往里加。要得到真正的菜单栏，只能由本程序自己开窗口，把画面装进去。

## What Changes

- 新增主窗口：无系统标题栏，自绘一行顶栏，从左到右依次是标题、`设备 / 音频 / 视图 / 帮助 / 关于` 菜单、最小化 / 最大化 / 关闭按钮
- 顶栏同时承担拖动、双击最大化、窗口贴边分屏的职责
- scrcpy 启动后，找到它的窗口句柄，去掉边框，嵌入主窗口的内容区并填满
- 菜单栏分五组：
  - 设备：切换设备（动态列表）、重命名、唤醒并解锁、重新连接
  - 音频：启动 / 停止、暂停·继续（手机）、缓冲、音频格式
  - 视图：窗口置顶、帧率、显示手机画面、全屏
  - 帮助：快捷键说明、查看日志、打开使用说明
  - 关于：版本信息
- 置顶改为设置主窗口的 `TopMost`，**立即生效，不再重启 scrcpy**
- 睡眠遮罩（手机已息屏）从独立浮窗改为主窗口内的覆盖控件
- 关闭主窗口 = 停止投屏，托盘保留；托盘图标双击重新打开窗口
- 纯音频模式不创建窗口
- 托盘右键菜单保留，与窗口菜单共用同一批操作入口

## 非目标

- 不改 scrcpy 源码，不重新编译 scrcpy
- 不做多窗口 / 多标签管理
- 不改变投屏与音频的采集参数（帧率、缓冲、编码仍走原有逻辑）

## 风险

- 跨进程嵌入 SDL 窗口属于非官方用法，个别版本或机型可能失败。必须保留降级路径：嵌入失败时隐藏主窗口，画面回落到 scrcpy 自己的窗口，托盘提示一次
- 嵌入后 scrcpy 的关闭按钮消失，进程收尾方式要改（发 `WM_CLOSE`，必要时强杀）
- 窗口尺寸变化会触发 scrcpy 重新布局画面，高 DPI 下需要处理像素换算
- 去掉系统标题栏后，拖动、缩放、双击最大化、贴边分屏都得自己实现。任何一项漏了，窗口就会「拖不动」或「缩不了」，属于必须实测的部分
