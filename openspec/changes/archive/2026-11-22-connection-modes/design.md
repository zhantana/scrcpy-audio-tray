# 设计：连接方式识别与自动择优

## 连接方式怎么判断

adb 给出的序列号本身就能区分：

| 序列号形态 | 例 | 判定 |
|---|---|---|
| 纯字母数字，无冒号 | `R5CT30XXXXX` | USB |
| `IP:端口` | `192.168.1.29:43521` | Wi-Fi |
| mDNS 服务名 | `adb-XXXX._adb-tls-connect._tcp` | Wi-Fi |

不需要额外调 `adb devices -l` 之外的东西，也不依赖 `usb:` 前缀（部分厂商的 adb 版本不带）。

## 择优顺序

```
用户显式选过的 serial（还在线） → USB 设备 → Wi-Fi 设备 → 第一条
```

原来的逻辑是「有 IP 形式的就优先 IP」，方向正好反了：Wi-Fi 受路由抖动影响，USB 是直连。改为 USB 优先。

## 自动切换

每秒的设备轮询里顺带看一眼当前连接的形态，只在「形态发生变化」时动一次，避免抖动：

- 当前走 Wi-Fi，且出现同一机型（`model` 相同）的 USB 设备 → 切到 USB；正在转发则整路重启
- 当前走 USB，USB 消失，但有可用的 Wi-Fi 设备 → 清空 serial，交给 `Get-Serial` 回落到 Wi-Fi
- 只切一次，不来回跳。切换时托盘通知一行「已切换到有线连接」

`model` 相同才切，避免误把另一台手机当成同一台。

## Wi-Fi 地址持久化

`settings.json` 增加 `WifiTargets`（字符串数组，最多 8 条，去重，新的在前）。
启动时 `Connect-Saved` 依次 `adb connect`，失败静默跳过。
保留旧的 `wifi_target.txt` 读取，作为一次性迁移来源。

## 蓝牙为什么只能置灰

scrcpy 的数据通道是 adb，adb 只有 USB 与 TCP 两种 transport，Android 未开放蓝牙上的 adb 接口。因此蓝牙无法承载投屏或低延迟音频。菜单保留该入口并置灰，附说明文字，避免用户以为是功能缺失。

## 菜单结构

```
选择设备 ▸
  USB 有线 ▸     [在线 USB 设备 / 「未检测到，请插线并开启 USB 调试」]
  WiFi 无线 ▸    [已保存地址…] / 自动发现并连接 / 添加 IP… / 配对新设备…
  蓝牙（不可用）  [置灰]
  ─────
  [全部设备，带 [USB] / [WiFi] 标签]
  ─────
  重命名 / 清理无效 / 忘记密码 / 刷新
```
