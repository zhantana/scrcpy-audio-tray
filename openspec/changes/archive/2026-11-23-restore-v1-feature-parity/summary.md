# Summary: restore-v1-feature-parity

## 交付内容

补齐 v2 相对 v1 的 14 项功能缺口，全部实现（与 harden-v2-runtime 同批交付）：

1. **纯音频主线**：`Screen` 字段恢复「是否叠加画面」语义；启动自动纯音频转发（上次带画面退出则音频起播后再叠）；投屏开关 = 音频不中断的整路重启；启动 1.2s 后音量键 24→25 叫醒音频通路。
2. **统一轮询**：`DevicePoller`（1s 单节拍、后台执行、事件封送 UI）替代 per-feature 定时器与 `SleepMonitor`；方向轮询（2s，0.02 容差）、keep-awake（`KeepAwake` 备份/恢复/清残留）、实例计数接回（2 拍）、电源同步、`userStopped` 防复活。
3. **传输自动化**：USB↔WiFi 随设备列表检测切换（同机型 USB 抢切、消失回落 USB 优先、`_manualPick` 不被抢、5s 冷却）；启动 600ms 静默重连 + 失败 4s×2 重试，全程气泡。
4. **设备管理菜单**：mDNS 列表 + 同机型去重；USB/WiFi/蓝牙三组菜单；自动发现、添加、配对码配对；重命名、清理无效设备、忘记解锁密码、重新连接、刷新。
5. **窗口**：顶栏菜单、F11 全屏/Esc、托盘双击三分支、单实例互斥体（`Global\` 失败回退 `Local\`）。
6. **状态条**：交付时实现（`ChromeH=64`），随后被用户要求移除——由 `simplify-window-topbar` 归档取代，主 spec 已更新为单根「操作」菜单、无状态条。

## 验证

- `dotnet build` 0 警告；`--selftest` 通过（去重计数、mDNS、参数分支、热键多键拒绝）。
- 用户真机验证通过（2026-11-23）：纯音频启动/音量键叫醒/插拔线切换/重试/keep-awake 备份还原/实例接回/横竖屏/双击三分支/单实例；回归项（音频不丢样本、热键、v1 配置字段）无异常。
- 未验证项：无（状态条被后续变更移除，不再适用）。
- spec 增量（4 个新增场景：双击三分支、电源同步、单实例、全屏）已合并进主 spec。
