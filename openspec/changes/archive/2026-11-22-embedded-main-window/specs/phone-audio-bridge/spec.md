# 本次变更差异：投屏窗口集成菜单栏

## ADDED

### Requirement: 单行顶部栏

系统 SHALL 在投屏时提供一个本程序自己的窗口，窗口最上方只有一行，从左到右依次是标题、菜单、窗口按钮，不得拆成标题栏加菜单栏两行。

#### Scenario: 投屏时出现带菜单的窗口

- **GIVEN** 手机已连接，用户开启投屏
- **WHEN** scrcpy 开始推流
- **THEN** 出现一个窗口，顶部只有一行
- **AND** 该行内从左到右为：窗口标题、`设备 / 音频 / 视图 / 帮助 / 关于` 菜单、最小化 / 最大化 / 关闭按钮
- **AND** 手机画面显示在这一行下方的内容区，不被遮挡

#### Scenario: 拖动与缩放窗口

- **GIVEN** 主窗口已打开
- **WHEN** 用户按住顶部栏空白处拖动，或拖动窗口边缘
- **THEN** 窗口跟随移动或改变大小
- **AND** 画面随内容区同步缩放

#### Scenario: 双击顶部栏

- **GIVEN** 主窗口处于普通大小
- **WHEN** 用户双击顶部栏空白处
- **THEN** 窗口最大化，再双击还原

#### Scenario: 菜单与托盘功能一致

- **GIVEN** 主窗口已打开
- **WHEN** 用户在窗口菜单中选择「视图 → 窗口置顶」
- **THEN** 与在托盘菜单中执行同一项的效果相同
- **AND** 两处的勾选状态保持一致

#### Scenario: 窗口关闭

- **GIVEN** 投屏正在进行
- **WHEN** 用户点击顶部栏右侧的关闭按钮
- **THEN** 停止投屏
- **AND** 主窗口隐藏，托盘图标保留
- **AND** 再次双击托盘图标可重新打开窗口

### Requirement: 画面嵌入主窗口

系统 SHALL 将 scrcpy 的画面窗口嵌入主窗口内容区，并随主窗口缩放同步尺寸。

#### Scenario: 嵌入后画面正常

- **GIVEN** scrcpy 已启动并产生窗口
- **WHEN** 系统完成嵌入
- **THEN** 画面填满内容区，比例不失真，多余区域为黑边
- **AND** 鼠标点击、滑动可以正常操作手机
- **AND** 键盘输入传递到手机

#### Scenario: 缩放窗口

- **GIVEN** 画面已嵌入
- **WHEN** 用户拖动窗口边缘改变大小
- **THEN** 画面随内容区同步缩放，不出现留白或错位

#### Scenario: 嵌入失败降级

- **GIVEN** 目标系统的窗口嵌入失败
- **WHEN** 投屏启动
- **THEN** 画面回退到 scrcpy 自己的独立窗口显示
- **AND** 托盘提示一次「画面已回退到独立窗口」
- **AND** 音频转发、解锁等功能不受影响

### Requirement: 置顶即时生效

系统 SHALL 在切换窗口置顶时立即改变窗口层级，不重启投屏进程。

#### Scenario: 打开置顶

- **GIVEN** 投屏进行中，窗口未置顶
- **WHEN** 用户执行「视图 → 窗口置顶」
- **THEN** 窗口立刻显示在其他窗口之上
- **AND** 画面与声音不中断、不闪烁
- **AND** 状态写入 `settings.json`，下次启动沿用

#### Scenario: 取消置顶

- **GIVEN** 窗口当前置顶
- **WHEN** 用户再次执行「视图 → 窗口置顶」
- **THEN** 窗口恢复普通层级
- **AND** 同样不重启投屏

## MODIFIED

### Requirement: 手机息屏提示

息屏提示 SHALL 显示在主窗口内容区内部，而不是作为独立浮窗覆盖在桌面上。

#### Scenario: 手机意外息屏

- **GIVEN** 投屏进行中
- **WHEN** 手机息屏且连续两次检测确认
- **THEN** 窗口内容区被黑底提示层覆盖，显示「手机已息屏」和「唤醒并解锁」按钮
- **AND** 菜单栏保持可用
- **AND** 点击按钮后提示层撤除，画面恢复

## REMOVED

### Requirement: 置顶需重启生效

原「切换置顶会重启投屏、画面闪断一两秒」的行为取消。
