# 总结：投屏窗口改为单行顶栏

## 做了什么

投屏从「scrcpy 自己的裸窗口」改成「本程序自己的窗口」，顶部一行里同时有标题、菜单和窗口按钮：

```
手机音频 - 设备名    设备  音频  视图  帮助  关于           ─  □  ×
┌────────────────────────────────────────┐
│              手机画面                   │
└────────────────────────────────────────┘
运行中 · 投屏 · 无损 40ms · 60fps
```

## 实现要点

- 窗口无边框（`BorderlessForm`，`Add-Type` 编译），`WM_NCHITTEST` 补回四边四角的缩放命中，顶栏拖动走 `WM_NCLBUTTONDOWN/HTCAPTION`，顺带拿到贴边分屏
- 顶栏 `Dock=Top`，内含标题 `Label` + `MenuStrip` + 三个自绘按钮（Segoe MDL2 字形，关闭悬停变红）
- 布局按优先级分配：菜单宽度优先保证，标题在窗口变窄时自动缩短，窄到放不下就隐藏
- 画面嵌入：`--window-title=ScrcpyBridge|<serial>` 定位窗口 → `ShowWindow(SW_HIDE)` → 去掉 `WS_CAPTION` 等样式并加 `WS_CHILD` → `SetParent` 到内容区 → `SetWindowPos` 填满 → `SWP_SHOWWINDOW`
- 异步附着：`Start-AttachTimer` 每 250ms 试一次，最多 6 秒，避免阻塞 UI
- 尺寸同步：只在内容区 `Resize` 时改子窗口大小，不每秒调用
- 置顶改为直接设 `TopMost`，即时生效，不再重启 scrcpy
- 息屏提示改为内容区内的覆盖面板，用 `SetWindowPos(embed, overlay, ...)` 把画面压到提示层下面
- `Stop-Audio` 改用 `PostMessage(WM_CLOSE)`，因为嵌入后的子窗口没有系统菜单，`CloseMainWindow` 会失效
- 备用入口：窗口菜单与托盘菜单是两套实例，共用动作函数，勾选状态由 `Sync-WindowMenu` 双向对齐

## 降级

`Ensure-MainForm` 失败（C# 编译不出来、Win32 声明失败）或 `SetParent` / `SetWindowPos` 失败时：恢复 scrcpy 原窗口样式并显示，主窗口隐藏，托盘提示一次。音频、解锁、快捷键全部照常。

## 验证情况

- 语法检查通过
- 1.3.0 安装包编译通过，脚本已部署到 `%LOCALAPPDATA%\ScrcpyAudioTray`
- **实机未验证**：本机安全策略禁止执行 `.ps1` 与 `Add-Type`，窗口创建、嵌入、拖动、缩放都没能自己跑一遍。tasks 里 7.2–7.7 保持未勾选

## 已知风险

1. 跨进程 `SetParent` 嵌 SDL 窗口属于非官方用法，少数环境会失败，已保留降级
2. 嵌入瞬间 scrcpy 窗口可能闪现一下（已在 `Start-Audio` 里先立主窗口来缓解）
3. 高 DPI 依赖 `SetProcessDPIAware()`，设置失败时画面位置可能偏
4. 无边框窗口的最大化边界靠 `MaximizedBounds` 限制在工作区，多显示器切换后需要重新设（已在 `Resize` 里重设）

## 修复（1.3.1）

### 1. 多出一个命令行黑窗

1.3.0 为了让 scrcpy 的窗口能被嵌入，去掉了 `-WindowStyle Hidden`。但 scrcpy.exe 是控制台程序，普通启动会给它分配控制台，于是桌面多一个黑窗。

改为 `ProcessStartInfo` + `UseShellExecute=false` + `CreateNoWindow=true`：只抑制控制台，画面窗口照常创建，也就不必再靠 `ShowWindow` 把窗口从隐藏状态顶出来。

### 2. 画面比例不对、窗口拖着没反应

两个原因叠在一起。

**DPI**：系统缩放 125%，本进程未声明 DPI 感知，坐标是缩放后的逻辑像素；scrcpy 是 DPI 感知的，按物理像素。把它的窗口 `SetParent` 进来后，系统会再缩放一次画面，尺寸和比例都对不上。

- 脚本最顶部（任何窗口创建前）调 `SetProcessDPIAware()`，用 `GetDpiForSystem()` 取缩放比，老系统退回读注册表 `AppliedDPI`
- 界面尺寸统一按 `dpiScale` 计算，窗体 `AutoScaleMode=None`，避免 WinForms 再缩一遍造成两套缩放
- `GripSize` 同步放大到 `10 × scale`

**鼠标命中**：画面铺满内容区时，窗口四边 10px 也属于 scrcpy 子窗口，主窗口的 `WM_NCHITTEST` 收不到，拖边缘没有反应。

- 内容区四边各留 `10 × scale` 内缩，画面四周露出一圈深灰，鼠标落在这一圈才归主窗口管
- `Attach-ScrcpyWindow` 与 `Sync-EmbedSize` 的坐标、尺寸都带上这个偏移

### 3. 顶栏盖住手机画面顶部、窗口还是拖不动（1.3.2）

根因是 `WS_POPUP`。

SDL 建的窗口是弹出窗口（带 `WS_POPUP`）。之前只摘掉了 `WS_CAPTION` / `WS_THICKFRAME` / 系统菜单，唯独漏了 `WS_POPUP`。仅靠 `SetParent` 并不会改这个样式——`SetParent` 只换父窗口，不动样式。

后果有两个：

- 弹出式窗口不受父窗口区域裁剪，于是它画到内容区之外，把顶栏压在下面（表现为「手机画面顶部被顶栏盖住」其实是反过来：画面盖住了顶栏，或者两者互相遮挡）
- 鼠标落在边缘时命中的是这个不裁剪的子窗口，主窗口收不到 `WM_NCHITTEST`，所以拖边缘改大小完全没反应

修法：样式掩码加上 `0x80000000`，一次摘掉 `POPUP | CAPTION | THICKFRAME | MINIMIZEBOX | MAXIMIZEBOX | SYSMENU`，再置上 `WS_CHILD`；改完用 `SWP_FRAMECHANGED` 让新样式立即生效。

同时把可拖边缘从 10px 提到 12px，抓取更容易。

### 4. 顶栏仍然压着画面、尺寸还是调不动（1.3.3）

前一条不是根因。真正的问题在**布局方式**。

顶栏、内容区、状态条三块原来都用 `Dock`。WinForms 处理 Dock 的顺序是按控件加入顺序**倒着来**：最后加的 `Fill` 内容区先被处理，直接把整个客户区吃掉；顶栏和状态条后处理时已经没空间，只能变成盖在内容区上面的两条。

表现完全对得上用户看到的现象：

- 画面从窗口最顶端（y=0）开始画，顶部被顶栏盖住
- 内容区高度等于整个窗口，scrcpy 按这个高度算画面比例，所以比例是错的
- 拖窗口边缘时画面跟着整块变，但可见区域被两条盖着，怎么调都别扭

改成不用 Dock，三块自己摆：

- 顶栏 `(0, 0, W, 38×scale)`
- 状态条 `(0, H-24×scale, W, 24×scale)`
- 内容区 `(0, 顶栏高, W, H - 顶栏 - 状态条)`

全屏时顶栏和状态条隐藏，内容区自动占满。

另外补了两道保险：

- 启动 scrcpy 时直接带 `--window-width/--window-height`，按内容区大小开窗，第一帧就是对的尺寸
- 嵌入后用 `GetWindowRect` 读回真实尺寸，对不上就用 `MoveWindow` 强设，最多试三次；结果写进 `tray-error.log`，以后再出问题有据可查

### 5. 顶栏不见了、边缘还是拖不动（1.3.4）

**顶栏消失**是自己写的布局函数留的坑：它拿「顶栏当前 Height」当作要分配的高度，而控件第一次被调用时还没排版、`Visible` 为 false，算出的高度是 0；于是把顶栏高度真的设成了 0，下一次再读 Height 还是 0，从此永久消失。

改为把顶栏 38×scale、状态条 24×scale 存成独立常量，布局只认常量，不再回读控件自身尺寸。全屏与否也改用 `fullScreen` 标志判断，不再看 `Visible`（父窗体未显示时 `Visible` 恒为 false）。

**边缘拖不动**：原来先调 `base.WndProc` 让系统算命中结果，再判断「结果是不是 HTCLIENT」才决定要不要返回缩放值。但 WinForms 内部可能改写这个结果，判断经常不成立，边缘就永远返回普通客户区。

改为完全不依赖系统的返回值：自己用鼠标屏幕坐标算落在哪条边，直接给出 `HTLEFT` / `HTTOP` 等值。无边框窗口没有非客户区，自己算反而更准。

### 6. 边缘仍然拖不动 + 左右大片黑边（1.3.5）

**拖不动**的最后一层原因：窗口没有 `WS_THICKFRAME`。

`FormBorderStyle=None` 建出来的窗口**不带**这个样式。没有它，系统收到我们返回的 `HTLEFT` 也不会进入缩放流程——消息发出去了，系统不认。

改为标准做法：

- `FormBorderStyle=Sizable`，先把 `WS_THICKFRAME` 拿到手
- 处理 `WM_NCCALCSIZE` 并让它返回 0，客户区铺满整个窗口，标题栏和边框都不绘制

这样外观还是无边框，但缩放、贴边分屏走的是系统原生实现，不再依赖运气。

**左右黑边**：竖屏手机（1440×3168）塞进 775px 宽的窗口，画面按高度缩放后只有 476px 宽，两边各剩 150px 黑边。

改为启动时按手机分辨率算一次窗口宽度：`内容区高 × 手机宽高比 + 两侧留边 + 一点标题余量`，贴着画面收窄。同时把最小宽度从 520×scale 放宽到 400×scale，允许窗口真的窄下来。

### 7. 边缘仍然拖不动 + 黑边仍在（1.3.6）

前两条都不是根因。真正的原因是**消息到不了窗口**。

内容区 `Panel` 铺满了整个客户区。鼠标落在边缘时，`WindowFromPoint` 命中的是这个 Panel，Windows 把 `WM_NCHITTEST` 发给 Panel，窗口自己的 `WndProc` 根本收不到——所以样式改对了、算得也对，代码就是不执行。

修法：内容区四边各缩进 `embedInset`，缝里没有任何子控件，鼠标落在缝上才归窗口管。顶栏和状态条仍占满整宽（否则菜单和按钮挤不下）。嵌入的画面改为填满内容区（偏移 0）。

黑边则改成按比例定窗口大小：

- 宽度先取「菜单放得下的最小宽度」= 416×scale
- 高度 = `内容区宽 ÷ 手机宽高比 + 顶栏 + 状态条 + 两侧缝`
- 算出的高度超过屏幕可用高度 95% 时，反过来以高度为准推宽度

竖屏手机（1440×3168）算出约 520×1192 的窗口，画面正好铺满，左右无黑边。只在每次启动时自动算一次，之后用户自己拖过的大小不会被覆盖。
