# C# / .NET 8 重构（v2）

## Why

现有实现是 3163 行 PowerShell + WinForms，把托盘、窗口、嵌入、热键、adb、解锁、配置全塞在一个脚本里，靠全局变量和事件回调串起来。跨进程嵌入 scrcpy 窗口这件事本身不受官方支持，1.3.x 一段连续修了十余次（顶栏被盖、边缘拖不动、黑边、比例错、全屏退不出、双窗口闪现、横竖屏反复）——问题不在某个判断写错，而在架构站不住。继续往上加功能，只会让修复成本越来越高。

用户目标：效果最好、帧数最高、画质最好、功能多样。

必须先讲清一件事：**帧数和画质的上限由 scrcpy 和手机编码器决定，与外壳用什么语言写无关。** 手机是 1440×3168@90Hz，实测瓶颈在编码器、不在带宽。重构能带来的是稳定、可扩展、功能多；帧数画质靠编码参数（码率、编码格式、帧率、传输通道）另做，这些在新架构里做成可视化设置，比现在改配置文件直观。

## What Changes

- 用 **C# + .NET 8 + WPF** 重写为 v2，替代 PowerShell 外壳
- 现有 PowerShell 版本**完整保留、不删不改**，作为可回退的稳定版
- 配置 `settings.json`、设备别名、解锁密码等数据格式向后兼容，v1 用户升级不用重设
- 继续用 scrcpy 5.0.1 + adb 作为投屏引擎，不改 scrcpy 源码
- 继续用 Inno Setup 打包，默认安装目录不变，保留自定义目录选项

## 架构目标

- 托盘、全局热键、菜单栏、多窗口、DPI、高刷全用 Windows 原生能力，不再靠 Add-Type 拼 Win32 声明
- 投屏窗口默认走 **scrcpy 原生窗口**（稳定）；嵌入自绘窗口作为可选项，失败自动降级
- 每个职责一个模块，可单独测试，不再是一个巨型脚本

## 帧数 / 画质（与语言无关，v2 里做成界面设置）

- 视频码率可调，默认提高到 16Mbps（现为 scrcpy 默认）
- 编码格式可选 H.264 / H.265 / AV1
- 帧率可选，放开到手机原生 90（现锁 60）
- 分辨率不降（不加 `--max-size`），由用户按需选
- 连接优先 USB，降低抖动

## 功能扩展（重构后容易加）

多设备同时开窗、投屏窗口截图 / 录屏、音量独立控制、快捷键方案可视化配置、主题、设备分组管理。

## 非目标

- 不改 scrcpy 源码、不重新编译 scrcpy
- 不重造 adb 协议栈
- 不一次性重写全部功能，分阶段迁移，每阶段可独立验证

## 风险

- C# / WPF 学习成本与开发周期长于改 bug
- 全局热键在游戏管理员权限下仍需进程提权，v2 沿用当前 UAC 启动方案
- 配置兼容需要写迁移层，旧字段不能丢
- 嵌入模式是跨进程老问题，v2 默认不走，只保留为可选
