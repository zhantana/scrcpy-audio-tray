# 本次变更差异：补齐 v1 功能缺口

现行 spec 已把目标行为全部定义（v1 的行为被完整继承进 spec），本变更不修改已有 Requirement 的语义，只是让 v2 实现追上 spec。因此 MODIFIED 部分不重复抄写现有场景，仅补充 spec 尚未覆盖的新增行为。

## ADDED

### 场景：托盘双击三分支

- 运行中且主窗口可见时双击托盘 → 停止转发
- 运行中但窗口隐藏时双击 → 显示主窗口
- 未运行时双击 → 启动音频转发

### 场景：停止转发时同步电源状态

- 转发停止时手机屏幕亮着且锁屏 → 补发一次 POWER 键，让显示电源状态与实际一致
- 不改变解锁状态，只同步电源

### 场景：单实例

- 托盘程序已运行时再次启动 → 提示已在运行后退出
- 两个实例不得同时抢同一台设备

### 场景：全屏

- 主窗口按 F11 进入全屏，顶栏保留
- 再按 F11 或 Esc 退出全屏

## MODIFIED（实现层面的缺口，行为以现行 spec 为准）

以下 Requirement 的行为在 spec 中已定义，本变更使 v2 实现与其对齐，不引入新的行为约定：

- 无线音频转发：纯音频转发成为一等路径（不强制投屏）；启动后音量键叫醒音频通路
- 设备发现与选择 / 连接方式 / 手动添加与配对设备 / 设备别名 / 无效连接清理：设备菜单三组结构、mDNS 去重、四入口、重命名、清理、忘记解锁密码
- 连接方式：USB↔WiFi 自动切换与回落
- 启动行为：启动即自动转发、失败重试 ×2、手动停止后不复活
- 投屏期间不自动息屏：`screen_off_timeout` 备份/恢复/残留清理
- 多路投屏抢占声音后自动接回：实例计数接回
- 窗口跟随视频流方向：2 秒周期方向轮询
- 单行顶部栏：五根菜单 + 底部状态条
